# MISSION.md 格式

`MISSION.md` 位于工作区根目录，记录用户学这个主题的**原因**。每个教学决策（下一步教什么、推荐什么资源、设计什么练习）都应能追溯到这份文档。

## 模板

```md
# Mission: {主题}

## Why
{1–3 句话。用户追求的具体现实目标：掌握这项技能后，他们的生活或工作有什么改变？避免「为了理解 X」这类抽象表述，追问到底层的结果。}

## Success looks like
- {一件具体、可观察的事，用户将能做到}
- {另一件}
- {……}

## Constraints
- {时间、预算、既有承诺、学习偏好——一切约束方法的东西}

## Out of scope
- {用户明确表示现在不追的相邻主题，保护最近发展区}
```

## 规则

- **一个工作区一个使命。**用户想学两个不相干的东西，那就是两个工作区。
- **具体压倒抽象。**「十月前跑完半马」胜过「变得更健康」；「给团队交付一个 Rust CLI」胜过「学 Rust」。
- **对模糊要顶回去。**用户说不清为什么学，就先访谈再动笔。烂使命比没有使命更糟。
- **现实变了就修订。**使命会变。目标移动时更新本文件：别让一份过时的使命继续给后续会话指路。
- **保持短。**`MISSION.md` 超过一屏，它就不再是罗盘，而成了计划。
